# 后端模块目录

`apps/server/src/main.ts` 是全系统组合根，`app.ts` 是 HTTP 组合根；二者只从各模块的 `index.ts` 导入。模块目录已经表达业务名，内部文件不再重复业务前缀。

```text
modules/
├─ automation/          index.ts http.ts types.ts
│  ├─ flows/            manager engine mode manual demand protection safety-bridge
│  ├─ state/            actuator snapshot
│  ├─ rules/            temperature
│  └─ adapters/         config.mysql reading
├─ safety/              index.ts types.ts
│  ├─ state/            supervisor freshness
│  ├─ rules/            build-flow low-flow over-pressure over-temperature
│  │                    sensor-timeout temperature-reversed heating-no-rise
│  └─ faults/           catalog definitions
├─ control/             index.ts http.ts types.ts
│  ├─ flows/            execute
│  ├─ rules/            policy
│  └─ adapters/         mysql command device-report
├─ realtime/            index.ts
│  ├─ flows/            receive
│  ├─ rules/            vstatus
│  └─ adapters/         sensor-message sensor.mysql
├─ device/              index.ts http.ts presence.ts mysql.ts
├─ sensor-history/      index.ts http.ts types.ts mysql.ts
├─ behavior/            index.ts http.ts types.ts
│  ├─ flows/            recognize
│  └─ adapters/         recognition.http behavior.mysql
├─ fault/               index.ts http.ts report.ts ports.ts mysql.ts
├─ diagnostics/         index.ts
│  ├─ flows/            diagnose
│  ├─ state/            confirmation
│  └─ rules/            hydraulic
├─ monitoring-config/  index.ts mysql.ts
├─ water-flow/          index.ts accumulate.ts calculation.ts types.ts mysql.ts
└─ operational-metrics/ index.ts runtime.ts
```

- `flows/`：安排步骤、调度副作用，不藏具体判断条件。
- `state/`：维护每设备状态、确认窗口与锁存事实。
- `rules/`：纯计算和判断，不直接连接数据库、MQTT、WebSocket。
- `adapters/`：MySQL、赛方 HTTP、设备报文或 MQTT 命令格式。
- `index.ts`：模块对外接口；新增跨模块能力先审查该接口，不直接从应用组装层导入内部路径。

安全授权、设备发布与故障上报仍由原有后端流程处理；本次只改变代码位置与导入路径，水力判定和水量计算抽取为行为等价的纯规则。
