# 智能识别模版使用

本文用于比赛现场配置智能识别 HTTP 接口，也可直接交给本地 Qwen3.5 9B 阅读。配置必须以赛方正式接口文档和真实请求、响应示例为准；字段不明确时停止配置，不得猜测。

## 工作链路

```text
历史数据页勾选记录
→ POST /api/behaviors/recognize
→ 后端按 ID 重新读取 t_sensor_data
→ recognition.json 生成现场 HTTP 请求
→ responseDataPath 提取识别结果对象
→ t_behavior_field_mapper 映射字段
→ 写入 t_behavior_data
→ 行为数据页展示
```

- 一次只能选择同一设备的数据，数量为 1～500 条。
- 识别输入由后端重新查询，不能由浏览器伪造传感器值。
- 行为识别不使用 MQTT 或 WebSocket。
- 配置错误、接口失败或结果字段未命中时，不会写入行为数据。

## 配置文件

路径为 `apps/server/config/recognition.json`，默认内容如下：

```json
{
  "url": "",
  "method": "POST",
  "bodyType": "json",
  "timeoutMs": 10000,
  "headers": {
    "Content-Type": "application/json"
  },
  "requestTemplate": {
    "rows": "$rows"
  },
  "responseDataPath": "data"
}
```

`url` 为空表示智能识别未配置。后端在每次识别时重新读取该文件，开发模式下一般不需要重启；现场无法确认加载状态时，重启后端最稳妥。文件必须是标准 JSON，不能写注释或尾随逗号。

## 配置字段

### `url`

填写完整接口地址，例如：

```json
"url": "http://192.168.1.50:9000/infer"
```

只有识别服务和后端在同一台电脑时才能使用 `localhost` 或 `127.0.0.1`；否则填写识别服务电脑的局域网 IP，并检查防火墙和端口。

### `method` 与 `bodyType`

方法支持 `GET`、`POST`、`PUT`、`PATCH`。

| `bodyType` | 行为 |
|---|---|
| `json` | 把模板结果作为 JSON 请求体发送 |
| `form` | 顶层字段作为表单参数；对象和数组转成 JSON 字符串 |
| `query` | 顶层字段作为 URL 查询参数；对象和数组转成 JSON 字符串 |
| `none` | 不发送参数 |

`GET` 只能搭配 `query` 或 `none`。

### `timeoutMs`

接口超时时间，单位为毫秒，必须为正整数，最大 `120000`：

```json
"timeoutMs": 30000
```

### `headers`

普通 JSON 接口：

```json
"headers": {
  "Content-Type": "application/json"
}
```

需要 Token：

```json
"headers": {
  "Content-Type": "application/json",
  "Authorization": "Bearer 比赛现场Token"
}
```

不要把真实比赛 Token 提交到 Git，比赛结束后及时移除。

## 请求模板变量

`requestTemplate` 会递归替换：

| 变量 | 内容 |
|---|---|
| `$rows` | 全部选中记录，按采集时间升序排列 |
| `$firstRow` | 第一条记录 |
| `$selectedCount` | 选中数量 |
| `$firstRow.字段名` | 第一条记录的指定字段，支持点路径 |

示例：

```json
"requestTemplate": {
  "samples": "$rows",
  "sample_count": "$selectedCount",
  "device_no": "$firstRow.deviceNumber",
  "first_pressure": "$firstRow.pressure"
}
```

传感器行通常类似：

```json
{
  "deviceNumber": "e46488d793245429",
  "recordedAt": "2026-09-18 16:28:40",
  "pressure": 22.7,
  "temp_out": 36.4,
  "temp_in": 36.4,
  "flow_rate": 3.42,
  "heat_Y1": 1,
  "water_Y2": 1
}
```

实际字段取决于 `t_sensor_field_mapper.p_name`。模板只支持替换，不支持计算、条件、循环或字符串插值。只有完整字符串等于模板变量才会替换；`"设备-$firstRow.deviceNumber"` 不会生效。

## 响应路径

`responseDataPath` 用英文句点定位响应中的结果对象。例如响应为：

```json
{
  "code": 0,
  "data": {
    "result": {
      "action": "移动加热棒",
      "confidence": 0.92
    }
  }
}
```

应配置：

```json
"responseDataPath": "data.result"
```

最终路径必须得到 JSON 对象，不能得到字符串、数字、布尔值或数组。响应根对象本身就是结果时，可填空字符串。

## 行为字段映射

结果必须匹配 `t_behavior_field_mapper` 才能写入 `t_behavior_data`。优先通过 `contest_admin` 的行为字段映射页面配置。

| 字段 | 含义 |
|---|---|
| `f_name` | 页面显示名称 |
| `db_name` | 存储列，只允许 `field1`～`field10` |
| `p_name` | 结果对象中的字段或点路径 |
| `unit` | 单位，可为空 |
| `type` | `1` 按数字展示，其他值按字符串展示 |
| `visible` | `1` 表示在行为数据页显示 |

若提取结果是 `{ "action": "移动加热棒", "confidence": 0.92 }`：

| `f_name` | `db_name` | `p_name` | `type` | `visible` |
|---|---|---|---|---|
| 行为名称 | `field1` | `action` | 字符串 | `1` |
| 置信度 | `field2` | `confidence` | `1` | `1` |

嵌套结果可以使用 `classification.action` 这样的点路径。当前本机只有 `text_field → field4` 的测试映射，赛方接口确定后必须按真实响应修改，否则不会入库。

## 完整示例

赛方要求 POST JSON，请求字段为 `samples` 和 `sample_count`，响应结果位于 `result.behavior`：

```json
{
  "url": "http://192.168.1.50:9000/infer",
  "method": "POST",
  "bodyType": "json",
  "timeoutMs": 30000,
  "headers": {
    "Content-Type": "application/json",
    "Authorization": "Bearer abc123"
  },
  "requestTemplate": {
    "samples": "$rows",
    "sample_count": "$selectedCount"
  },
  "responseDataPath": "result.behavior"
}
```

若提取后的对象包含 `action` 和 `confidence`，行为映射的 `p_name` 就分别填写这两个字段。

## 比赛现场使用步骤

1. 从赛方取得 URL、方法、鉴权、请求示例和响应示例。
2. 确认识别服务电脑的 IP、端口和防火墙。
3. 按响应对象在 `contest_admin` 配置行为字段映射。
4. 编辑 `apps/server/config/recognition.json`。
5. 检查 JSON 格式并清除示例 Token。
6. 在历史数据页选择同一设备的 1～3 条记录。
7. 点击“智能识别”。
8. 在行为数据页检查保存结果。
9. 在操作历史确认“发起智能识别”和“智能识别结果”。
10. 小样本成功后再增加数量，最多 500 条。

## 常见错误

| 现象 | 检查内容 |
|---|---|
| 智能识别接口尚未配置 | `url` 为空 |
| HTTP 401/403 | Token、请求头或鉴权格式错误 |
| HTTP 404 | URL 路径错误 |
| HTTP 422 | 查看返回的配置、路径或映射中文错误 |
| responseDataPath 没有得到对象 | 路径错误或目标为数组/字符串 |
| 没有匹配任何行为字段 | `p_name` 与提取后的对象不一致 |
| 一次只能选择同一设备 | 勾选了不同设备的数据 |
| 请求超时 | 接口未启动、网络不通或超时配置过短 |

如果接口要求图片/文件上传、流式或非 JSON 响应、签名算法等协议，当前模板不能表达。必须取得完整文档后修改 `apps/server/src/modules/behavior/adapters/recognition.http.ts`，不能猜测字段继续实现。

## 交给千问的任务模板

将赛方真实请求和响应示例附在提示词后：

```text
请阅读 AGENTS.md、docs/比赛协作指南.md 和 docs/智能识别模版使用.md。

根据我提供的赛方正式接口文档，只完成：
1. 生成 apps/server/config/recognition.json。
2. 列出 t_behavior_field_mapper 应配置的 f_name、db_name、p_name、type、visible。
3. 用示例历史数据推演最终 HTTP 请求。
4. 用赛方响应推演 responseDataPath 和字段映射结果。
5. 判断当前模板能力是否足够。

不得猜测缺失字段，不得修改 MQTT、设备控制、安全规则或数据库结构。资料不足时列出需要向赛方确认的问题，不要继续写代码。
```

千问输出后，人工对照赛方文档逐项核对 URL、请求头、请求体字段、响应路径和行为映射，再进行小样本测试。
