# 第五里程碑：智能识别与行为数据闭环

[返回重构计划目录](../重构计划.md)

### 目标

提前做好比赛现场离线可配置的智能识别闭环：“历史传感器数据勾选 → 后端调用现场 HTTP 识别接口 → 按后台字段映射保存结果 → 行为数据页面动态展示”。比赛现场拿到接口文档后，只修改本地识别配置并在 `contest_admin` 配置行为字段，不重写页面主体。

### 已确认边界

- 行为数据不是设备主动上报的数据，后端不订阅 `device/behavior`。
- 行为页面只通过 HTTP 查询数据库，不使用 MQTT 或 WebSocket。
- 识别入口位于历史数据页面，用户勾选一至多条已保存的传感器记录后主动点击“智能识别”。
- 后端根据记录 ID 重新查询数据库，不信任前端提交的整行传感器数据。
- 行为结果继续写入 `t_behavior_data`；字段映射读取 `t_behavior_field_mapper`，只允许写入 `field1` 至 `field10`。
- `p_name` 对应识别响应字段，`db_name` 对应数据库槽位，`f_name/unit/type/visible` 决定页面展示。
- 不修改数据库结构，字段映射仍由独立 `contest_admin` 维护。

### 离线接口适配

- 配置文件固定为 `apps/server/config/recognition.json`，包含接口地址、HTTP 方法、超时、请求头、请求 JSON 模板和响应数据路径。
- 请求模板支持 `$rows`、`$firstRow`、`$selectedCount`，由后端替换为勾选的传感器业务数据。
- 比赛现场只需按文档修改 JSON 并重启后端；配置为空时给出明确中文提示，不发送请求。
- 响应数据路径必须解析为对象，再按 `t_behavior_field_mapper.p_name` 提取字段并参数化入库；没有任何字段命中时拒绝保存。

### 交付内容

1. `modules/behavior`：行为查询仓储、动态字段映射、识别适配服务和 HTTP 路由。
2. `POST /api/behaviors/recognize`：接收唯一历史记录 ID 数组，调用识别接口并保存一条行为结果。
3. `GET /api/behaviors/options`：返回当前可见行为字段。
4. `GET /api/behaviors`：按识别时间分页查询，动态返回配置字段。
5. 历史数据表格增加多选列和“智能识别”按钮；成功后进入行为数据页面。
6. 启用 `/behaviors`，动态生成行为结果表头，支持时间筛选和分页。
7. HTTP 响应拦截器继续打印请求方法、URL、请求头、参数、状态码和响应。

### 测试与验收

- 识别适配测试请求模板、响应路径、HTTP 失败和未配置提示。
- 仓储测试历史 ID 查询、字段白名单、动态结果映射、无字段命中拒绝和单次入库。
- HTTP 测试参数校验、成功响应和可操作的失败信息。
- 页面验证未勾选提示、识别中状态、成功跳转、动态表头、空状态、筛选与分页。
- 在 `1366×768` 和 `1920×1080` 下无横向溢出。
- 运行相关测试、完整测试与 `pnpm typecheck`；按约定不运行生产构建。

### 明确不做

- 不订阅或发布行为 MQTT Topic，不新增行为 WebSocket 消息。
- 不猜测比赛方真实字段或写死某种识别模型协议。
- 不在前端直接调用识别服务或直接写数据库。
- 不修改 `contest_admin` 和现有数据库结构。
