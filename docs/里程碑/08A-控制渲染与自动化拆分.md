# 第八里程碑补充：配置化控制渲染与自动化拆分

### 实施结果（2026-09-14）

- 指令树与 `contest_admin` 保持一致：同级配置按 `id` 排序，`ref_id` 建立父子关系，`ref_value` 决定条件分支是否显示。
- `f_type` 完整映射为：1 开关、2 输入框、3 滑块、4 日期时间、5 单选、6 多选；前端不再把第 4 类误渲染为仅时间选择器。
- 自动模式开启仍由后端安全门校验完整且新鲜的传感器数据、故障锁定和当前安全规则；关闭自动模式始终允许。HTTP 409 表示当前事实不满足切换条件，不是前端按钮失效。
- `automation-engine.ts` 保留单设备状态的协调职责；人工指令发布和模式切换分别下沉到 `automation-manual-control.ts`、`automation-mode-control.ts`，对外接口不变。
- 每类确定性安全判断已放入 `modules/safety/rules` 的独立纯规则文件，包括建流、低流、超压、超温、传感器超时、探头装反和加热无温升；故障中文说明集中在 `safety-fault-definitions.ts`。

### 兼容约束

- `master` 只切换后端自动状态机，不直接发布 MQTT。
- 数据库存储结构、MQTT Topic、设备报文和已有 HTTP 对外含义均未改变。
- `CONTROL_CONFIG_INVALID` 与 `COMMAND_PUBLISH_FAILED` 是配置/基础设施失败入口，不是传感器判定规则，继续由自动化协调层触发，再统一进入安全锁定。
- 本补充只改善渲染一致性和比赛现场可读性，不放宽第八里程碑安全保护。
