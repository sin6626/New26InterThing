# 第二里程碑补充：实时监控趋势图

[返回重构计划目录](../重构计划.md)

### 现状

实时监控首页已经通过 WebSocket 接收 `sensor.realtime`，能够按设备展示最新传感器值，但当前没有实时趋势图。原第二里程碑曾明确把实时曲线留到后续，本补充阶段负责补齐这部分展示能力。

### 目标

在不修改 MQTT 协议、数据库结构和后端控制逻辑的前提下，将每条已成功入库并通过 WebSocket 推送的传感器数据追加到当前设备的有限时间窗口，使用 ECharts 固定展示三张实时图：“全部传感器趋势”“温度趋势”“流量趋势”。

### 已确认的三图结构

1. **全部传感器趋势**：展示当前映射中全部可绘制的数值型传感器字段，包括温度、流量、压力以及比赛现场新增的其他数值字段。
2. **温度趋势**：只突出入口温度 `temp_in` 与出口温度 `temp_out`，显示各自曲线；显示名称和单位仍取 `t_sensor_field_mapper`，不在页面写死中文表头。
3. **流量趋势**：当前阶段展示瞬时流量 `flow_rate`；显示名称和单位同样来自字段映射。
4. 三张图共享同一设备、同一时间窗口与同一批实时点，不能各自重复维护 WebSocket 数据。
5. 温度图和流量图不是通过中文名称模糊匹配字段，而是使用已确认的设备协议字段 `temp_in`、`temp_out`、`flow_rate`，避免后台改显示名称后图表失效。
6. 旧项目流量图中的管内流速、累计总流量，以及温度图中的温差、升温速度和热功率属于后续水循环与累计量里程碑。当前只为这些派生序列预留组合位置，不提前计算或伪造；对应后端能力完成后再接入同一张温度图或流量图。

### 数据与状态设计

1. 继续只消费现有 `sensor.realtime` 消息，不新增 MQTT Topic 或 WebSocket 消息类型。
2. 在实时模块中按 `deviceNumber` 独立维护点列，切换设备时直接切换对应窗口，禁止多设备数据串图。
3. 每个点保存 `recordedAt` 和本次消息中的动态字段；字段名称继续来自后端映射结果，不写死温度、压力或流量。
4. 只有能够可靠转换为有限数字的字段进入全部传感器图；温度图只读取 `temp_in`、`temp_out`，流量图只读取 `flow_rate`。文本、空值、图片地址等仍可显示在最新值卡片中，但不生成曲线。
5. 每台设备默认保留最近 60 个点，允许页面切换为 30、60、120 个点；达到上限后移除最早数据，避免比赛长时间运行造成浏览器内存持续增长。
6. 同一设备、同一 `recordedAt` 的重复消息覆盖原点而不是追加，避免 MQTT 重发造成重复横坐标。
7. 时间轴使用设备记录时间；无法解析的时间不进入趋势图，但不影响最新值卡片更新。

### 初始数据与断线恢复

1. 页面首次进入时，使用现有传感器历史趋势接口为当前设备补充最近窗口，避免必须等待新 MQTT 消息后才出现曲线。
2. WebSocket 断线期间不伪造或插值数据，图表保留最后一次有效窗口，并明确显示实时通道状态。
3. WebSocket 重连成功后，重新请求当前设备最近窗口，再继续接收实时增量，弥补断线期间遗漏的数据。
4. 历史补拉与实时消息合并时按时间排序并去重；后到的实时数据优先覆盖相同时间点。
5. 补拉失败只显示趋势加载错误，不清空最新值卡片，也不阻断后续 WebSocket 实时追加。

### 前端交付

1. 新增可复用的 `RealtimeTrendChart.vue`，由三张图分别传入标题和序列，集中封装 ECharts 初始化、更新、缩放、窗口尺寸变化和销毁。
2. 新增实时趋势状态模块，负责按设备缓存、动态数值字段发现、排序、去重和窗口裁剪；页面不直接操作 ECharts 数据结构。
3. 在实时监控首页的最新值卡片下方先放一张通栏“全部传感器趋势”，再在下一行左右并排放置“温度趋势”和“流量趋势”；窄至 `1366×768` 时仍保持桌面双栏并保证图例可读。
4. 三张图共用 30、60、120 点窗口选择，以及折线图、柱状图、散点图切换；默认使用折线图和 60 点窗口。
5. 图例使用动态字段名称；字段较多时允许图例滚动，鼠标悬停显示完整时间和值。
6. 每张图独立显示空状态：没有设备或全部无数值字段时显示“暂无传感器趋势”；缺少温度映射时显示“未配置入口/出口温度字段”；缺少流量映射时显示“未配置流量字段”。空状态下不创建对应 ECharts 实例。
7. 图表颜色保持稳定：同一字段在切换设备、窗口长度或图表类型后仍使用同一颜色，方便现场观察。
8. 页面继续适配 `1366×768` 与 `1920×1080`，不得产生整体横向滚动；图表容器随窗口变化调用 `resize()`。

### 后端影响

- 不新增实时专用接口，首次加载和重连补偿复用现有 `GET /api/sensor-history/trend`。
- 不修改 `sensor.realtime` 结构，不新增数据库查询模块。
- 如果现有历史趋势按分钟聚合与实时秒级点无法可靠合并，实施时应将补拉数据明确标记为分钟点并统一时间精度，不能猜测或静默制造重复点。

### 测试 seam

- 实时窗口 seam：按设备隔离、追加、相同时间覆盖、时间排序和 30/60/120 点裁剪。
- 字段 seam：全部图动态发现数值字段；温度图只选择 `temp_in`、`temp_out`；流量图只选择 `flow_rate`；三类均保留数值 `0`，排除 `null`、空字符串、非有限数字和普通文本。
- 合并 seam：历史补拉与实时数据按统一时间精度去重，实时数据覆盖同时间历史点。
- 生命周期 seam：WebSocket 首次连接不重复创建连接；重连后触发一次当前设备补拉。
- 图表只执行 TypeScript 检查和真实浏览器验证，不为 ECharts 像素实现编写脆弱测试。

### 验收场景

1. 页面打开后能从历史接口看到当前设备的“全部传感器”“温度”“流量”三张最近趋势，无需等待新消息。
2. 连续收到 `sensor.realtime` 后，最新值卡片和图表同步更新，不刷新页面。
3. 切换设备后，三张图同时切到对应设备，不显示上一台设备的数据。
4. 重复时间消息不会产生两个横坐标；超过窗口上限后内存与点数保持稳定。
5. 全部图包含压力等其他数值字段，温度图只有入口/出口温度，流量图只有当前已有的瞬时流量；文本和空值不进入图表，数值 `0` 能正确显示。
6. MQTT 或 WebSocket 中断时页面不崩溃；恢复后补齐当前窗口并继续更新。
7. `1366×768` 与 `1920×1080` 下图例、工具栏和图表可正常操作，无横向溢出。
8. 相关自动化测试、完整测试和 `pnpm typecheck` 通过；按项目约定不运行生产构建。

### 明确不做

- 不实现历史数据页面已有的复杂筛选和分页。
- 不把实时趋势数据再次写入数据库。
- 不在前端进行安全保护、故障判断、PID 或控制决策。
- 不为缺失时间或断线区间生成虚假数据。
- 不增加图表图片素材、SVG 装饰或与业务无关的动画。
- 当前阶段不实现管内流速、累计总流量、温差、升温速度或热功率；这些派生量等待对应后端控制里程碑完成后接入现有三图结构。
